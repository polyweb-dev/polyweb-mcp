## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 REST and MCP use one shared execution service and give identical project attribution and provider decisions for the same request.
- [x] #2 Every usage row, trace span (root, child and fanout), admission and rate attempt carries the verified project and actor; attribution never comes from caller input or trace baggage.
- [x] #3 A project can bind several credentials of one provider and pin or fan out across them; it can use only its private credentials and system credentials explicitly granted to it.
- [x] #4 Health, quota observations, limit links and circuit breakers are keyed to the credential or the shared pool; one credential failing does not disable an unrelated credential.
- [x] #5 Strict caps hold atomically across processes and transports: concurrent requests never exceed a pool or project window, keys in one pool share one allowance, and in the 4/6 example project A stops at 4/s while B is idle.
- [x] #6 A capacity-store failure rejects new constrained execution; retries never duplicate a reservation or skip a new attempt charge.
- [x] #7 No provider call happens before scope, permission, binding and capacity checks pass.
<!-- AC:END -->
